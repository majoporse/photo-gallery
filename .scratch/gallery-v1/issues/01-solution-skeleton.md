# 01 — Solution skeleton, configuration, health endpoint

Status: ready-for-agent
Blocked by: none

## Context
Nothing exists yet. This ticket creates the shape every later ticket builds inside: four projects, the dependency rule enforced by project references, and a contract pipeline that actually produces `contracts/openapi.json`.

## Scope
- `backend/Gallery.sln` with `src/Gallery.Domain`, `src/Gallery.Application`, `src/Gallery.Infrastructure`, `src/Gallery.Api`, plus `tests/Gallery.Domain.Tests` and `tests/Gallery.Api.Tests`.
- .NET 10 LTS. Nullable enabled, `TreatWarningsAsErrors`, central package management via `Directory.Packages.props`.
- Minimal API host with route group `/api/v1`, `GET /health`, `ProblemDetails` for every error, and request logging.
- Options binding for `ConnectionStrings:Gallery`, `Storage`, `Admin`, `Auth`, `Cors`.
- Build-time OpenAPI export: `Microsoft.Extensions.ApiDescription.Server` writing `contracts/openapi.json` on `dotnet build`.
- Compose-free local run: `dotnet run` starts, health answers, and startup fails loudly with a clear message when required config is missing.

## Done when
- `dotnet build` is warning-free.
- `GET /api/v1/health` returns 200 with a body.
- `contracts/openapi.json` exists, is regenerated by build, and contains the health path.
- `Gallery.Domain` and `Gallery.Application` reference no infrastructure packages (verified by `dotnet list package`).

## Comments

Implemented. Deviations, all deliberate:

- **`Gallery.slnx`**, not `Gallery.sln` — the .NET 10 SDK now emits the XML solution format by default, and `dotnet sln add` / `dotnet test` handle it.
- **xunit 2.9.3** instead of xunit.v3: the .NET 10 SDK refuses `dotnet test` for Microsoft.Testing.Platform projects unless you opt into the new runner, and that opt-in is not worth it for three tests. Revisit when MTP is the default.
- **Health is split.** `GET /health` is liveness and always answers 200 (what the ingress uses); `GET /health/ready` returns 503 and names the missing settings, so a pod with incomplete config never goes Ready. The missing-config log is skipped when the entry point is invoked by the OpenAPI generator (it passes `--applicationName=…`), otherwise every build would print a fake outage.
- **`tests/Gallery.Domain.Tests` deferred to ticket 02** — there is no domain type to test yet, and a placeholder test is worse than none.

Verified: build warning-free, three tests pass, `contracts/openapi.json` is OpenAPI 3.1.1 containing both health paths, and both inner projects reference zero packages.
